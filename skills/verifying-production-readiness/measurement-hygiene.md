# 측정 위생 — 수치를 무효로 만드는 것들

**오염된 창에서 잰 수치는 틀린 수치보다 나쁘다.** 틀린 수치는 의심받지만 오염된 수치는 초록색으로 보인다.

## 재기 전 확인 (매번)

```bash
uptime                              # 로드 평균 — 코어 수 대비
ps -Ao pid,pcpu,etime,command | sort -k2 -rn | head -5   # 폭주 프로세스
df -h                               # 디스크 여유
```

**실측 사례**: 「지금 머신은 조용하다」고 전제하고 측정했는데, 부모가 죽어 고아가 된 빌드 프로세스가 **250% CPU 를 3시간째** 먹고 있었고 15분 로드 평균이 12.45였다. 그 창의 수치는 전부 버려야 했다.

## 수치를 무효로 만드는 것

| 오염원 | 증상 | 대응 |
|---|---|---|
| **다중 에이전트가 공유 테스트 DB** | FK 위반 · 401 · 설명 안 되는 실패 | 격리 DB 복제. 스키마 덤프가 **데이터 행**을 안 옮겨 마이그레이션이 재실행되는 아티팩트를 알고 있어라 |
| **외부 부하** | 타임아웃(단언 실패 아님) | 조용한 창에서 재실행. **타임아웃과 단언 실패를 구분**하라 |
| **측정 중 프로세스 사망** | 처리량 0 구간 | 그 창 폐기. watch 류는 자식 크래시를 안 살리므로 며칠씩 죽어 있을 수 있다 |
| **재시작 직후** | 큐 급증 · 워밍업 | 부팅 시 고아 작업 재발행이 있으면 그건 **생산량이 아니다**. 안정화 후 재측정 |
| **자원 고갈** | SIGBUS · OOM · 무한 대기 | 디스크·스왑 여유 확인. mmap 페이지인 실패는 SIGBUS 로 나타난다 |
| **캐시 효과** | 첫 회만 느림 | 콜드/웜 분리. 순서 효과 제거를 위해 **역순으로도** 재라 |

## 창(window) 규칙

- **최소 10분** — 60초 창은 노이즈가 지배한다
- 창이 **재시작·배포·크래시를 걸치면 버린다**
- 오염된 창도 **폐기하지 말고 「오염」으로 표시해 남긴다** — 전후 비교가 근거가 될 때가 있다
- **언제 잰 값인지** 항상 적는다. 날짜 없는 수치는 다음 세션에서 못 쓴다

## 「고쳤다」 이후

수정 후 재측정은 **같은 조건**이어야 한다. 조건이 달라졌으면 그건 비교가 아니다.
그리고 **한 한계를 걷어내면 다음 한계가 드러난다** — 메모리 다음은 포맷 한계, 그다음은 타임아웃. 재측정에서 새 결함이 나오면 **새 ID 로 대장에 올린다.**

## 격리 통과는 무죄 증명이 아니다

격리 실행에서 8/8 통과하던 것이 **진짜 제품 결함**이었던 사례가 있다. 격리는 「이 변경이 만든 회귀인가」를 가르는 도구지 「결함이 없다」는 근거가 아니다.
