# 11축 — 무엇을 · 어떻게 · 판정선 · 흔한 착각

각 축은 독립 파일에 기록한다(`NN-<axis>.md`). 병렬로 돌릴 때는 **축마다 소유 파일을 갈라** 충돌을 막는다.

심각도는 4단계 고정: **BLOCKER**(출하 차단) · **HIGH** · **MED** · **LOW**.
BLOCKER 정의를 축마다 다르게 쓰지 마라 — **「이 상태로 고객에게 가면 데이터·보안·가용성 중 하나가 실제로 깨진다」** 하나로 통일한다.

---

## ① 기능 완성도 · 경쟁 벤치마크

**무엇을** 팔려는 것이 실제로 있는가. 카테고리별로 경쟁 제품 대비 어디까지 왔는가.

**어떻게**
- 제품 카테고리를 10~20개로 나누고 **가중치**를 매긴다(핵심 축은 가중치를 높인다).
- 각 카테고리를 0~5로 채점하되 **점수마다 근거 화면·코드**를 붙인다.
- 경쟁 제품의 같은 카테고리를 실제로 확인한다(문서·체험판). 기억으로 쓰지 마라.

**판정선(예시)** 총점 75/100 이상 + **핵심 축 전부 4 이상** + 기능 BLOCKER 0.
→ 판정선은 착수 전에 정한다(Iron Rule 1).

**흔한 착각** 「기능이 있다」와 「쓸 수 있다」는 다르다. 화면은 있는데 저장이 안 되거나, API 는 있는데 UI 진입점이 없는 것이 흔하다. **진입점부터 결과 확인까지 이어서** 보라.

## ② 백엔드 · API

**무엇을** 계약·권한·에러·트랜잭션 경계.

**어떻게**
- **라우트 전수 목록**을 뽑고(코드에서 생성) 각각: 인증 필요? 권한 검사 위치? 입력 검증? 페이징 상한?
- **권한 매트릭스**: 역할 × 리소스 × 동작. 비권한 계정으로 **실제 호출**해 403 을 확인한다(코드 독해로 대체 금지).
- **트랜잭션 경계**: 「합계와 목록이 같은 스냅샷인가」 류의 불변식을 코드가 **선언만 하고 안 지키는지** 본다. 격리 수준이 `READ COMMITTED` 면 한 트랜잭션 안에서도 statement 마다 스냅샷이 새로 뜬다.
- **에러 계약**: 4xx/5xx 형태가 일관적인가. 스택 트레이스·내부 경로가 응답에 새는가.
- **N+1 · 무한 페이징**: 상한 없는 목록 API 를 찾는다.

**판정선** 인증·권한 우회 0 · 입력 검증 누락 0 · 상한 없는 목록 0.

**흔한 착각** 「같은 규칙이 두 벌 있는데 한쪽만 고쳤다」가 이 축 최대 사고 유형이다. **규칙이 복제돼 있으면 그 자체를 결함으로 올려라**(하나로 추출).

## ③ UI · 접근성

**무엇을** 디자인 스펙(정본 문서·디자인 시스템이 있다면 그것) 대비 일치, 상태별 렌더, 접근성 불변식.

**어떻게**
- **상태 매트릭스**로 훑는다: 빈 상태 · 로딩 · 오류 · 권한 없음 · 긴 텍스트 · 많은 항목 · 오프라인.
- **변형 곱하기**: 라이트/다크 × 브랜드 스킨 수(있다면) × 로케일(있다면) × 주요 화면. 자동화로 색 대비를 전수 측정한다(WCAG AA: 본문 4.5:1, 큰 글자·비텍스트 3:1).
- 반응형 브레이크포인트마다 **히트 타깃 44px** 과 가로 스크롤 발생 여부.
- 키보드만으로 주요 플로우 완주. 포커스 링·포커스 트랩·모달 esc.

**판정선** AA 미달 0(불가피한 예외는 개별 사유 기재) · 키보드 완주 가능 · 상태 매트릭스에 빈칸 0.

**흔한 착각** 「선언이 있다」는 근거가 아니다. CSS 특이도·상위 요소 `overflow` 때문에 선언이 안 먹는 일이 흔하다 — **라이브 실측값**으로 확인하라.

## ④ 사용성 · E2E 워크플로우 시뮬레이션 🔴 빼지 마라

**무엇을** 실제 사람이 처음부터 끝까지 해낼 수 있는가.

**어떻게**
- **페르소나 3~5명**(신규 관리자 / 일반 멤버 / 외부 협력자 / 관리자 운영)과 각 5~10단계 시나리오.
- 헤드리스 브라우저로 **실제 조작**한다. 단계마다 스크린샷을 근거로 남긴다.
- 생성물에 **공통 접두사**를 붙이고 기존 데이터를 지우지 않는다(감사 흔적 분리).
- 각 단계를 **성공 / 부분성공 / 실패 / 미검증**으로 판정하고, 부분성공은 「무엇이 부족했는지」를 적는다.
- **마찰(friction)** 도 기록한다 — 실패는 아니지만 사람이 멈칫한 지점.

**판정선** 시나리오 실패 0. 부분성공은 사유와 함께 허용.

**흔한 착각** 「테스트가 그 경로를 덮는다」 — 덮지 않는다. **실측 사례**: 정적 감사 축 전부가 놓친 출하 차단 결함(대용량 내보내기 한 번이 API 서버 전체를 수 분간 정지)을 **이 축만 잡았다.** 사람이 하는 순서로, 사람이 쓰는 데이터 크기로 해 봐야 나온다.

## ⑤ 성능 · 부하

**무엇을** 실제 데이터 크기에서 무너지는 지점.

**어떻게**
- **실데이터 규모를 먼저 정한다**(문서 N만 건, 첨부 N GB, 동시 사용자 N). 그 숫자 없이 재지 마라.
- 주요 엔드포인트에 **p50/p95/p99** 와 **동시 요청**에서의 거동. 단일 요청 지연만 보면 큐잉을 놓친다.
- **한 요청이 전체를 멈추는가** — 대용량 내보내기·리포트·마이그레이션이 이벤트 루프·커넥션 풀·워커를 독점하는지. **이게 가장 흔한 출하 차단이다.**
- 메모리: 큰 입력에서 스트리밍인지 전량 버퍼인지. **한계를 넘겨 실제로 터뜨려 본다.**
- DB: 느린 쿼리 로그 · 인덱스 미스 · 커넥션 풀 상한 대비 인스턴스 수.

**판정선** 단일 작업이 서비스 전체를 정지시키지 않음 · p95 목표 충족 · 상한 초과 입력에서 **명확한 오류**(무한 대기·OOM 아님).

**흔한 착각** 「내 노트북에서 빨랐다」. 그리고 **한 한계를 걷어내면 다음 한계가 나온다** — 메모리 다음은 파일 포맷 한계, 그다음은 타임아웃이다. 재측정 없이 「고쳤다」 하지 마라.

## ⑥ 보안

**무엇을** 인증·인가·세션·비밀·전송·저장.

**어떻게**
- **인증**: 비밀번호 정책·잠금·강제 변경·세션 만료·토큰 폐기(비밀번호 변경 시 기존 토큰·PAT 회수되나?).
- **인가**: ②의 권한 매트릭스를 **공격자 관점**으로 다시 — ID 를 바꿔 남의 리소스에 접근(IDOR), **테넌트 경계 넘기**(워크스페이스·조직·프로젝트 등 격리 단위).
- **파일 서빙**: 업로더가 지정한 `Content-Type` 을 그대로 `inline` 으로 내보내면 **저장형 XSS**다. `nosniff` 는 **명시된** `text/html` 을 막지 못한다.
- **비밀**: 저장소 이력 전체를 비밀 스캐너로(`gitleaks`/`trufflehog`). 현재 트리만 보면 삭제된 비밀을 놓친다.
- **헤더·CSP**: 프로덕션 번들 + 실제 서빙 경로에서 확인. **dev 서버에는 헤더가 없어 검증 자체가 불가능하다.**
- **로그**: 비밀번호·토큰·개인정보가 로그로 새는가.

**판정선** 인증·인가 우회 0 · 저장형 XSS 0 · 이력 비밀 0 · 보안 헤더 실측 확인.

**흔한 착각** **「넣었다」로 끝내는 것.** CSP·보안 헤더는 **역검증**이 필요하다 — 일부러 위반을 유발해 실제로 막히는지 본다. 그래야 「위반 0」이 *정책 부재*가 아님이 증명된다.

## ⑦ 취약점 · 공급망

**무엇을** 의존성·이미지·라이선스.

**어떻게**
- 생태계별 의존성 감사(`npm/pnpm audit` · `pip-audit` · `cargo audit` · `govulncheck` 등)를 돌리되 **총 건수로 판정하지 마라.**
- **프로덕션 도달 여부를 추적**한다: 런타임 번들에 실제로 포함되는가, 실행 경로에 있는가, 다른 계층(CSP·네트워크 격리)이 차단하는가.
- 컨테이너 이미지 스캔(베이스 이미지 CVE). 고정 태그·다이제스트 사용 여부.
- 라이선스: 배포 형태(온프레미스·SaaS)와 충돌하는 라이선스가 없는가.

**판정선** **프로덕션 도달 critical/high = 0**. 나머지는 사유와 함께 잔여로.

**흔한 착각** 「devDependency 라 상관없다」 — **빌드 타임 공급망 공격은 devDependency 로 들어온다.** 상관없다고 말하려면 도달 경로를 실제로 추적한 결과를 대라.

## ⑧ 논리 오류 · 데이터 정합성

**무엇을** 코드가 스스로 선언한 불변식을 지키는가.

**어떻게**
- **코드 주석·문서가 선언한 불변식을 수집**한다(「총 N건 = 목록 행 수」, 「표시 = 강제」, 「A 를 지우면 B 도 지워진다」).
- 각 불변식에 대해 **깨지는 시나리오**를 만든다: 동시 쓰기 · 부분 실패 · 재시도 · 순서 뒤집힘.
- **경계값**: 0건 · 1건 · 상한 · 상한+1 · 음수 · 빈 문자열 · 유니코드 · 아주 긴 값.
- **상태 기계**: 불가능해야 할 전이가 실제로 막히는가(취소된 초대로 가입, 삭제된 문서에 댓글).
- **고아 데이터**: 사용자·테넌트 삭제 시 남는 것.
- **시간**: 타임존·DST·서버 시계 차이.

### 도메인 불변식 — 새 축을 만들지 말고 여기에 얹는다

제품마다 「이것이 깨지면 사업이 깨진다」는 규칙이 있다. **별도 축으로 분리하지 말고 ⑧ 안에 도메인 목록을 만들어라**(축 번호가 흔들리면 다음 세션이 대장을 못 읽는다). 착수 시 도메인 전문가·기획 문서에서 5~15개를 뽑는다.

| 도메인 | 대표 불변식 |
|---|---|
| 결제·정산 | 멱등성(같은 요청 두 번 = 한 번 청구) · 이중 결제 방지 · 통화 정밀도·반올림 · 부분 환불 합계 ≤ 원금 · 재처리 이벤트 중복 |
| 재고·주문 | 음수 재고 불가 · 예약과 실재고 합 일치 · 취소 시 복원 |
| 협업·문서 | 동시 편집 후 손실 0 · 권한 변경이 기존 세션에 즉시 반영 |
| 구독·과금 | 기간 경계 이중 청구 · 업/다운그레이드 비례 배분 |

**판정선** 선언된 불변식 위반 0 · **도메인 불변식 전건 검증** · 고아 데이터 경로 0.

**흔한 착각** 「같은 카드 안의 두 숫자가 서로 다르다」 같은 결함은 테스트가 잡지 못한다 — **두 숫자가 같은 소스에서 오는지**를 사람이 봐야 한다.

## ⑨ 결정성 · 재현성

**무엇을** 같은 입력에 같은 결과가 나오는가. 측정을 믿을 수 있는가.

**어떻게**
- **플레이키 테스트**: 전체 스위트를 **3회 이상 반복** 실행. 순서 무작위화. 격리 실행과 전체 실행의 차이.
- **격리 통과는 무죄 증명이 아니다** — 격리에서 8/8 통과하던 것이 실제 제품 결함이었던 사례가 있다.
- **빌드 재현성**: 같은 커밋에서 같은 산출물이 나오는가. 락파일 고정. 타임스탬프·랜덤 시드.
- **시간·난수 의존**: `Date.now()`·`Math.random()` 이 결과를 바꾸는 지점.
- **마이그레이션**: 빈 DB → 최신, 그리고 **구 버전 데이터 → 최신** 둘 다. 롤백 마이그레이션도.

**판정선** 3회 반복에서 결과 동일 · 설명 못 하는 실패 0 · 마이그레이션 양방향 성공.

**흔한 착각** 「가끔 실패하는데 재시도하면 돼요」 = 결정성 결함이다. 그리고 **테스트 DB 아티팩트**를 결함으로 오인하거나 그 반대로 결함을 아티팩트로 치부하는 일이 잦다 — 원인을 특정할 때까지 판정하지 마라.

## ⑩ 배포 · 롤백

**무엇을** 설치·업그레이드·되돌리기가 실제로 되는가.

**어떻게**
- **깨끗한 장비에서 설치를 처음부터** 1회(문서만 보고). 문서에 없는 단계가 나오면 그게 결함이다.
- **업그레이드**: 이전 버전이 돌던 상태에서 새 버전으로. 데이터 보존 확인.
- 🔴 **롤백 리허설**: 새 버전에 **고의로 결함을 주입**하고 되돌린다. 「롤백 스크립트가 있다」와 「롤백이 된다」는 다르다.
- **백업·복구**: 백업을 받아 **다른 장비에 실제로 복구**한다. 복구 시간을 잰다.
- 오프라인·에어갭 배포라면 번들에 빠진 것이 없는지(릴리즈 노트·라이선스·이미지).
- 설정: 필수 환경변수 누락 시 **명확히 죽는가**, 조용히 기본값으로 도는가.

**판정선** 설치·업그레이드·롤백·복구 **각 1회 이상 실제 성공**. 문서대로 재현 가능.

**흔한 착각** 「스크립트가 있으니 된다」. 이 축은 **해 보지 않으면 아무것도 검증되지 않는** 유일한 축이다.

## ⑪ 운영 · 관측성

**무엇을** 문제가 났을 때 알 수 있는가, 고칠 수 있는가.

**어떻게**
- **조용한 실패 사냥**: 예외를 삼키는 코드(`catch {}`·`log.warn` 만), fire-and-forget 작업, 재시도 없는 외부 호출. 각각 **실패했을 때 누가 아는가**를 물어라. 답이 없으면 결함이다.
- **헬스체크**가 실제로 의존성을 보는가(200 만 뱉는 껍데기인가).
- **메트릭·알림**: 큐 적체 · 실패율 · 지연 · 디스크·메모리. **임계 알림이 실제로 발송되는지 한 번 터뜨려 확인.**
- **로그**: 상관관계 ID, 레벨, 보존 기간, 개인정보 마스킹.
- **운영 작업**: 사용자 잠금 해제 · 재인덱싱 · 큐 비우기 같은 일을 **UI/CLI 로 할 수 있는가**, 아니면 DB 직접 수정이 필요한가.
- **자원 한계**: 디스크·스왑 여유. 장기 실행 프로세스가 죽었을 때 **자동 복구되는가**.

**판정선** 치명 실패에 알림 도달 · 조용한 실패 경로 0 · 헬스체크가 의존성 반영.

**흔한 착각** 「로그에 남아요」 — **아무도 안 보는 로그는 관측이 아니다.** 「한 달째 전부 실패해도 알 방법이 없다」면 그건 BLOCKER 급이 될 수 있다.

## 축 ↔ 모델 등급 — 판단이 필요한 곳에만 큰 모델을 쓴다

**lint 는 형식만 본다.** 인용이 실존하는지까지가 전부이고, 그 인용이 진짜 근거인지·시나리오가
의미 있었는지는 검사하지 않는다. 즉 **하방(거짓 「출하 가능」)은 도구가 막고, 상방(무엇을
발견하는가)은 모델이 정한다.** 약한 모델로 돌리면 틀린 판정이 아니라 **얕은 감사**가 나오는데,
그건 리포트에 「봤는데 괜찮았다」로 적힌다 — 형식상 정직하고 실질적으로 놓친 상태다.

| 등급 | 쓰는 곳 | 모델(작성 환경의 예시) |
|---|---|---|
| **설계·판단** | 오케스트레이터(범위 합의 · 게이트 확정 · 심각도 판정 · 최종 판정 · 이음매 점검 · 반박 채택) · **④ E2E · ⑥ 보안 · ⑧ 논리** | Fable 5 (`model: "fable"`) · 없으면 Opus 4.8 (`"opus"`) |
| **실행·회수** | ①②③⑤⑦⑨⑩⑪ — 도구를 돌리고 결과를 규격대로 회수 · 수정 라운드 구현 | Sonnet 5 (`"sonnet"`) · 다파일 통합·까다로운 수정은 Opus 4.8 |
| **기계적** | `evidence/` 정리 · lint 위반 형식 수리 · 표 정렬 · 로그에서 수치 추출 | Haiku 4.5 (`"haiku"`) |

**내리지 말아야 할 두 축은 ④와 ⑧이다.** ⑧은 「불변식이 깨지는 시나리오를 상상하는 것」이 곧
발견의 양이고, ④는 시나리오가 얕으면 아무것도 안 나온다 — 정적 감사 축 전부가 놓친 차단
결함을 ④가 혼자 잡은 사례가 그 증거다. 비용을 줄여야 하면 **실행·회수 등급을 먼저 내려라.**

**어느 모델로 감사했는지 축 파일에 적는다** — 위임 도구·버전을 적는 것과 같은 이유다.
Sonnet 이 본 축과 Fable 이 본 축은 **같은 등급의 증거가 아니다.** 다음 세션이 「이 축은 얕게
봤을 수 있다」를 알아야 재감사 우선순위를 정한다(⑨ 결정성의 재현 조건이기도 하다).

모델 이름은 **작성 환경의 예시**다 — 규약은 **등급(판단 강도)** 이고, 이름은 환경에 맞게 바꾼다.


## 축 선택

전 축이 항상 필요한 건 아니다. **빼는 건 되지만, 뺐다고 적어야 한다.**

**코어 4축 ④⑥⑧⑨ 는 어느 상황에서도 뺄 수 없다**(거짓 GO 방지 — `SKILL.md` 「착수 첫 단계」).
아래 「최소 축」은 코어 위에 **얹어** 읽는다 — 표에 코어가 안 보여도 코어는 항상 포함된다.
사용자가 범위를 골라도 코어는 선택지 밖이다.

| 상황 | 최소 축 (+ 코어 ④⑥⑧⑨ 항상) |
|---|---|
| 첫 상용 출시 | 전 축 |
| 기능 릴리즈 | ①②③ + 변경이 닿는 축 |
| 핫픽스 | ⑩ + 변경이 닿는 축 |
| 인프라·배포 변경 | ⑤⑩⑪ |

**「이 축은 이번에 보지 않았다」를 리포트에 남기지 않으면, 다음 사람이 「봤는데 괜찮았다」로 읽는다.**

## 축 ↔ 보조 도구 매핑 — 있는 도구를 다시 만들지 마라

환경에 아래 스킬·도구가 있으면 해당 축 감사를 **위임**하고, 결과를 그 축 파일과 대장으로
회수한다(근거 등급·`파일:줄` 규칙은 위임해도 동일하게 적용 — 도구 출력이 서술로만 오면
Iron Rule 2 의 세 요소를 적는다). 표의 스킬 이름은 **작성 환경의 예시**다 — 없는 것이
정상이며, 같은 역할의 다른 도구가 있으면 그걸 쓰고, 없으면 축의 「어떻게」대로 직접 한다.

| 축 | 위임 후보 | 회수할 것 |
|---|---|---|
| ③ UI·접근성 | `/design-review`(시각 품질) · `accessibility-review`(규격) | AA 실측표 · 스크린샷 |
| ④ E2E 사용성 | `/qa` `/qa-only` · `/browse`(헤드리스) | 단계별 판정 + 스크린샷 |
| ⑤ 성능·부하 | `/benchmark` | p50/p95/p99 · 전후 비교 |
| ⑥ 보안 | `/cso`(인프라·공급망) · `/security-review`(코드 취약점) | 발견별 파일:줄 · 재현 명령 |
| ⑦ 공급망 | 생태계 audit(`npm audit`·`pip-audit` 등) | 프로덕션 도달 추적 결과 |
| ⑧ 논리·정합성 | `/codex`(적대적 반박 — 불변식을 깨 보게 시킨다) | 반박된 불변식 · 재현 절차 |
| ⑨ 결정성 | 테스트 러너 3회+ 반복 스크립트 | 반복 로그(전부 evidence 로) |
| ⑪ 관측성 | `/canary`(배포 후 실측 감시) | 알림 도달 로그 · 이상 탐지 결과 |

**한 축에 도구를 겹칠 거면 「다른 렌즈」일 때만이다.** 같은 모달리티(정적 스캐너 둘)를 쌓으면
사각도 같이 움직이고, 같은 결함이 대장에 두 줄로 들어와 ID 만 흔들린다. 위 표에서 ③·⑥ 이
둘인 이유는 보는 각도가 다르기 때문이다(시각 품질 vs 접근성 규격 / 인프라·공급망 vs 코드).

착수 전 `bin/ensure-tools.sh --install` 로 존재를 확인한다 — CLI 는 자동 설치되고, 누락
스킬은 세션이 마켓플레이스 검색으로 설치를 시도한다. 그래도 없으면 축의 「어떻게」대로
직접 한다. **위임했다는 사실과 도구 버전을 축 파일에 적는다** — 다음 세션이 같은 방식으로
재현할 수 있어야 한다.
